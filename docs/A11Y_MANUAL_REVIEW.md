# Dashboard manual a11y review (WCAG 2.1 AA)

## Scope

Session 16 added `dashboard/e2e/localhost/accessibility.spec.ts`, which runs axe-core against the four public URLs (`/`, `/login`, `/privacy`, `/terms`) in both light and dark themes and gates on `serious` + `critical` violations at WCAG 2.1 AA tags. Lighthouse CI also pins `categories:accessibility >= 0.9` in `dashboard/lighthouserc.json`. This document covers the WCAG 2.1 AA checks that automated tooling cannot reliably detect: focus order, screen-reader announcement quality, language switching behaviour, landmark structure, focus management on navigation, reduced-motion support, and form-error semantics. The findings table below was produced by static review of the files listed in scope; the manual test plan is what a developer should run in a real browser and screen reader before merging changes that touch `dashboard/app/**`.

## Manual test plan

Run before merging any PR that touches `dashboard/app/**`. None of these are automated; reviewer is responsible for going through them in a real browser.

1. **Skip link** — Load `/`, press Tab once. The "Skip to content" / "İçeriğe atla" link should appear in the top-left, visibly focused. Press Enter; focus should jump into `<main>`.
2. **Tab order** — On every public page (`/`, `/login`, `/privacy`, `/terms`), Tab from the address bar through the whole page. Order should match reading order: skip link → privacy link in header → locale switcher (TR, EN) → theme toggle → page content. No "phantom" stops on offscreen elements.
3. **Locale switch updates `<html lang>`** — Open DevTools, inspect `<html>`. Click EN in the locale switcher. After the route refresh, `<html lang>` must change from `tr` to `en`. Reload and repeat for TR.
4. **Visible focus ring** — Tab through every interactive element on `/`, `/login`, `/privacy`, `/terms` in both light and dark theme. Each element must have a visible focus indicator. Pay attention to the landing-page CTA buttons (inline-styled) and the locale switcher pressed/unpressed states.
5. **Theme toggle focus retention** — Focus the theme toggle (Tab to it from the skip link), press Enter to switch theme. Focus must remain on the theme toggle button (do not let it jump back to the body).
6. **Locale switch focus retention** — Same drill: focus the locale switcher's TR/EN button, switch locale. After `router.refresh()`, focus may be lost; verify behaviour and document any drift. (Acceptable to land on body if the switch causes a full server re-render, but ideally focus stays on the pressed button.)
7. **Screen-reader announcement: theme toggle** — With NVDA (Windows) or VoiceOver (macOS), focus the theme toggle. SR should announce `"Karanlık moda geç / Switch to dark mode, toggle button, not pressed"` (or "pressed" when in dark mode).
8. **Screen-reader announcement: locale switcher** — Focus the TR or EN button. SR should pronounce "Türkçe" with Turkish phonology (because of `lang="tr"`) and "English" with English phonology.
9. **Login form errors** — Open `/login` with the dashboard NOT configured for Supabase. Type a malformed email and click "Send magic link". SR should announce the error via `role="alert"`. Tab to the input; SR should report it as `aria-invalid` and read the error via `aria-describedby`.
10. **Error boundary announcement** — Throw a deliberate error inside any client component (or trigger one via the React DevTools), let `app/error.tsx` render. SR should announce the error message immediately because of `role="alert" aria-live="assertive"`.
11. **Reduced motion** — Enable `prefers-reduced-motion: reduce` in DevTools (Rendering tab). Hover the theme toggle; the `transition-colors` hover should snap rather than animate. No layout should rely on transition timing.
12. **Headings outline** — Use a screen-reader heading-list shortcut (NVDA: H key; VoiceOver: VO+Cmd+H) on `/`, `/privacy`, `/terms`, `/login`. There should be exactly one h1 per page, and h2s should follow without skipping levels.

## Out of scope / future work

- **Real screen-reader testing**: NVDA on Windows and VoiceOver on macOS were not exercised here — only static review of the markup. Anyone running this manual test plan should record the SR output and note any deviations from expected announcements.
- **Auth-walled admin pages**: `/admin/sessions`, `/admin/analytics`, `/admin/feedback`, `/admin/users`, etc. were not reviewed. The axe-core spec only covers public URLs, and the admin Breadcrumb is the only shared a11y surface that has been spot-checked.
- **Focus management on App Router navigation**: Next.js 15 App Router does not auto-move focus to the new page's `<h1>` after `router.push` / `Link`. A future enhancement would add a `useFocusOnPageChange` hook that focuses `#main-content` (now present) on each pathname change.
- **Color contrast in non-default chroma settings**: Some users override system chroma / contrast at OS level (Windows High Contrast, macOS Increase Contrast). The OKLCH tokens in `globals.css` haven't been validated under those settings. axe-core only sees computed sRGB.
- **Mobile / RTL**: Dashboard messages currently ship `tr.json` + `en.json` only — no RTL locales exist, so `dir="rtl"` is not yet relevant. The mobile app's five-locale matrix is a separate audit (see Session 12 i18n contract).
- **Landing-page header consolidation**: Two visible top bars on `/` (the layout's sticky header + the landing page's own `<header>` nav) is a structural concern flagged above. Resolving it requires a design call about which controls live where.
